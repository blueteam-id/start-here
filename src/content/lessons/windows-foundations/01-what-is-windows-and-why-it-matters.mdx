## Before you start: getting access to Windows

In Linux Essentials, Windows users could use WSL. There is no built-in equivalent the other way: macOS and Linux cannot run Windows on their own. If you already use Windows every day, you are set; skip ahead. If not, you have a few free options:

- **A free evaluation VM.** Microsoft's [Evaluation Center](https://www.microsoft.com/evalcenter) offers a free 90-day **Windows 11 Enterprise evaluation** download. Install it in a VM with VirtualBox, VMware, UTM, or Hyper-V (the Computing Basics track's virtualization lesson explains what those are). This is the most common way to follow this track without owning a Windows machine. Microsoft has also offered ready-made developer VM images in the past, but those downloads have not always been available; the evaluation download is the dependable option.
- **On an Apple Silicon Mac (M1 or later),** you need the **ARM** version of Windows 11, not the usual x86_64 one. This is the architecture rule from Computing Basics Lesson 1 in practice: a VM uses the same processor architecture as its host. UTM and Parallels both run Windows 11 for ARM, and every command in this track works the same on it.
- **Dual boot or a spare machine.** An old laptop with Windows installed works just as well, and you keep it afterward.
- **A cloud free tier.** Several cloud providers offer a free Windows VM for a limited time, if you would rather not install anything locally.

Whichever you choose, this track only uses tools that ship with a normal Windows 10 or 11 install. Once Windows runs, there is nothing else to download.

## What "Windows" refers to

**Windows** is Microsoft's family of operating systems. Like "Linux", the name covers more than it first seems.

Modern Windows is built on the **Windows NT kernel**. Windows XP was the first home version built on it, replacing the older and much less robust DOS-based line (Windows 95, 98, and ME). Windows 10, Windows 11, and every Windows Server edition share the same NT kernel. That is why skills from this track carry across all of them, even though they look different.

Windows also comes in two product lines, and a defender should keep them apart:

- **Desktop editions** (Windows 10 and 11) run on employee laptops and desktops. These are the machines a phishing email or a malicious USB drive usually reaches first.
- **Windows Server editions** run the infrastructure behind those desktops: file servers, database servers, and, most importantly, **domain controllers**, the servers that run **Active Directory**.

**Active Directory** manages user accounts, permissions, and policies across a whole company network. Most businesses use it to run Windows at scale. One stolen domain administrator account can give an attacker control of every Windows machine in the company. That is a far bigger problem than one stolen laptop.

This is why incident response pays so much attention to Windows. Windows is not less secure than other systems. The **blast radius** of a Windows compromise, through Active Directory, often reaches much further. Lesson 4 explains Active Directory in plain terms.

## Why defenders spend so much time on Windows

Windows has dominated company desktops for decades. Most employees sit in front of it, so it is the most common first foothold in real intrusions:

- Phishing attachments, malicious macros, and drive-by downloads are mostly built for Windows, because that is where most targets are.
- Ransomware groups build their tools for Windows first, because the backup and file servers in a typical business also run Windows.

This does not mean Windows is weaker. It means a defender who only knows Linux is missing the system they will meet most: the helpdesk ticket about a strange popup, the laptop that needs triage after a phishing click, the server that suddenly behaves oddly. Nearly every blue team role expects you to know both Windows and Linux.

## A quick look under the hood

Open the Start menu, type `winver`, and press Enter. A small window shows your exact Windows edition and **build number**. The build number tells you which security patches should already be installed. Vulnerability advisories and support articles often ask for it first.

For a fuller picture, open a terminal (right-click the Start button and choose **Terminal**, or search for **PowerShell**) and run:

```powershell
systeminfo
```

This prints a long report: OS name and version, install date, manufacturer and model, total memory, and more. Read it slowly. You will see the same edition and build as `winver`, plus hardware details that matter during triage. For example, it shows whether the machine is physical or a virtual machine, which changes how you investigate it.

### What to notice

- Desktop Windows and Windows Server share the NT kernel. Active Directory, running on servers, is why one compromised account can affect a whole company.
- `winver` and `systeminfo` give you the exact build number, which patch advisories and troubleshooting guides ask for first.
- If you set up a VM or a spare machine for this track, keep it. A disposable Windows environment is useful for later security practice.
