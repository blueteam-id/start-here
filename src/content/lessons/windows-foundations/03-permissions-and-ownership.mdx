## NTFS permissions: more detailed than Linux's nine bits

Linux Essentials taught you to read a string like `-rwxr-xr--`: three fixed categories (owner, group, other), each with three rights (read, write, execute).

Windows's main filesystem, **NTFS**, uses a richer model called an **Access Control List (ACL)**. A file or folder carries a list of **Access Control Entries (ACEs)**. Each entry names one user or group and exactly which rights they get, such as Read, Write, Modify, or Full control.

This is more flexible than the Linux model. One file can give one person Read only, and another person Full control. But flexibility has a cost. A long, inconsistent ACL is easier to get wrong, and much harder to check at a glance, than a nine-character Linux string. That is why auditing Windows permissions carefully matters.

Every file and folder also has an **owner**, the same idea as on Linux. Most permissions are **inherited** from the parent folder instead of being set on each file. That is usually convenient. It is also why some permission problems are hard to find: the entry causing it may sit several folders above the file you are looking at.

## Reading permissions from PowerShell

Create a practice file and look at its permissions:

```powershell
Set-Location "$HOME\windows-foundations"
New-Item -ItemType File -Name "practice.txt" -Force
Get-Acl .\practice.txt | Format-List
```

`Get-Acl` returns the file's full ACL. The output is dense at first. Look for the `Access` property. It lists each entry as `<Principal> Allow <Rights>`, for example `BUILTIN\Users Allow ReadAndExecute, Synchronize`. Each line is one entry: who, and exactly what they can do.

For a shorter view, the older `icacls` tool is often faster to read. (The name stands for "Integrity Control ACLs". It comes from cmd.exe but works fine in PowerShell.)

```powershell
icacls .\practice.txt
```

This prints each principal with a short code in parentheses: `(F)` for Full control, `(M)` for Modify, `(RX)` for Read & execute.

- `BUILTIN\Users:(RX)` plus your own account with `(F)` is a normal, sane default.
- `Everyone:(F)` is the Windows version of a Linux file that is world-writable and executable. It deserves the same suspicion: anyone on the system can change or replace the file.

## Administrator, standard users, and UAC

Separately from file permissions, every Windows account has a **privilege level**:

- A **standard user** can use installed software and change their own files, but cannot make system-wide changes.
- An **Administrator** can make system-wide changes.

This matches the Linux idea of an ordinary user versus root. Windows adds one more layer: **User Account Control (UAC)**.

Even on an Administrator account, Windows does not run everything with full rights. Most of what you do runs with standard-user rights. When an action really needs admin rights, such as installing software, changing certain settings, or running a tool "as Administrator", Windows shows a **UAC prompt** and waits for your approval.

You have probably clicked through many of these without thinking. UAC exists so that a stray click, a malicious script, or compromised software cannot quietly take full control of the machine. Someone (you, or an attacker who already has your session) has to approve it first.

That is why **UAC bypass** is a well-known group of attack techniques. Malware that avoids the prompt, or tricks a user into approving it, has beaten the one barrier between "ran as a normal program" and "has full control of this machine". An unexpected UAC prompt, or one approved at a time you do not remember, is a real signal worth investigating.

Check your own account's privilege level:

```powershell
whoami /groups
```

Look for `BUILTIN\Administrators` in the output. If it is listed, your account is an administrator on this machine. As explained above, most of what you do still runs with standard rights until UAC elevates it.

### What to notice

- NTFS ACLs name exact users and exact rights instead of three fixed categories. That gives flexibility, but a permission problem can hide several folders up the inheritance chain.
- `Everyone:(F)` on a file you did not open up on purpose is the Windows version of Linux's `777`. Flag it the same way.
- UAC is the one deliberate pause between "a program ran" and "a program has admin control". An unexpected or unremembered approval is a real finding.
