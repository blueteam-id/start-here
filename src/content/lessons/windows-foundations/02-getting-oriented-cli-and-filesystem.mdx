## Two command lines, one Windows

Windows ships with two different command-line shells:

- **Command Prompt** (`cmd.exe`) is the older one, from the Windows NT days. It is still there mostly so old scripts and tools keep working.
- **PowerShell** is the modern shell, which Microsoft has built on since 2006. This track uses it almost all the time. One reason matters a lot in Lesson 5: PowerShell commands pass **structured data** to each other, not just plain text.

To open PowerShell, right-click the Start button and choose **Terminal** (Windows 11), or search for **Windows PowerShell** (Windows 10). You will see a prompt like this:

```powershell
PS C:\Users\alex>
```

Read it like a Linux prompt. `PS` means this is PowerShell, not cmd. `C:\Users\alex` is your **current directory**. It plays the role of `pwd` in Linux, but PowerShell shows it on every line. The default prompt does not show your username or the machine name, unlike a typical Linux prompt. When you need those, you ask for them; Lesson 3 shows how.

## Finding your way around

Three commands answer the same first questions as in a Linux shell. In PowerShell, each is a **cmdlet** (say "command-let") with a full name. Each also has short **aliases** that will feel familiar if you have used Linux:

```powershell
Get-Location    # full cmdlet name; alias: pwd
Get-ChildItem   # full cmdlet name; alias: dir, or ls
Set-Location    # full cmdlet name; alias: cd
```

Try the aliases:

```powershell
pwd
dir
```

`pwd` prints your current directory, like on Linux. `dir` lists what is in it: name, size, and last-modified time for each entry. The `Mode` column at the start of each line hints at type and attributes (`d` for directory, among others). It is much less detailed than the Linux permission string. Lesson 3 covers Windows permissions properly.

## The shape of the Windows file system

Linux has one filesystem starting at `/`. Windows organizes storage around **drive letters**. `C:` is almost always the main system drive. Other letters (`D:`, `E:`, and so on) are extra disks, USB drives, or network shares.

A few folders inside `C:\` are worth recognizing on sight:

- `C:\Windows`: the operating system itself, including the kernel, system DLLs, and built-in tools. You should almost never need to edit anything here.
- `C:\Program Files` (and `C:\Program Files (x86)` for older 32-bit software): installed applications.
- `C:\Users\<username>`: your personal space, like a Linux home folder. It contains `Desktop`, `Documents`, and `Downloads`. It also contains two normally hidden folders worth knowing by name, `AppData\Local` and `AppData\Roaming`, where applications store their settings and cached data.
- `C:\ProgramData`: shared application data, like `AppData` but for all users on the machine.

One folder deserves special attention: `AppData\Local\Temp`, often reached by typing `%TEMP%`. It is one of the most common places malware drops itself after a phishing download or a malicious script. The reason is simple: an ordinary user can already write there, with no special permission. Knowing this folder, and checking it during triage, is a small habit that pays off often.

## Creating your practice space

As in the Linux track, you will reuse one folder for every exercise, so you never touch a real file that matters. Create it now:

```powershell
New-Item -ItemType Directory -Path "$HOME\windows-foundations" -Force
Set-Location "$HOME\windows-foundations"
```

- `New-Item -ItemType Directory` creates a folder. It is PowerShell's more explicit version of `mkdir` (which also works as an alias).
- `-Force` means "no error if it already exists", so these two lines are safe to run again on another day.
- `$HOME` is a built-in variable for your user profile folder, `C:\Users\<you>`, so this works for anyone logged in.

From now on, when a lesson says "in your terminal", it means from inside `windows-foundations` unless it says otherwise.

### What to notice

- PowerShell and cmd.exe can both run on the same machine at the same time. Logs usually show which one launched a script or process, and that detail matters during an investigation.
- `%TEMP%` (`AppData\Local\Temp`) is writable by any ordinary user. It is one of the first places to check for a dropped file.
- You now have a `windows-foundations` folder for every exercise in this track, the same habit the Linux track built.
