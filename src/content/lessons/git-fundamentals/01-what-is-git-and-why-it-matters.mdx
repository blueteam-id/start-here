## What Git is

**Git** is a **version control system**. It tracks every change ever made to a set of files: what changed, who changed it, when, and why. It also lets you go back to any earlier version.

Git is **distributed**. Every copy of a **repository** (a project tracked by Git) holds the full history, not just the latest version. So there is no single central server whose loss would wipe out the project's past. Every copy is a complete backup.

Linus Torvalds, who also created the Linux kernel, built Git in 2005 to manage the kernel's development. Today it is by far the most used version control system in the world, for open source and company code alike.

## Why security teams end up living in Git

- **Infrastructure as code.** Firewall rules, cloud settings, and detection rules increasingly live as files in a Git repository, not as settings clicked into a console. When a rule is wrong, Git shows who changed it, when, and their explanation. That is exactly what an investigation needs first.
- **The software supply chain runs on Git.** Almost all software, open source and internal, passes through Git before it reaches production. Knowing Git lets you follow a supply-chain security advisory yourself, instead of taking it on faith.
- **It is a hard-to-fake audit trail.** Once other people have copies of a commit, quietly rewriting history is very hard to do without someone noticing, especially with the protections covered later. That is why Git history is trusted as a record of what happened.

You do not need to be a software developer for any of this. You need to be comfortable reading a tool that, more and more, is where the evidence lives.

## Installing and checking your setup

Open a terminal and check whether Git is already installed:

```bash
git --version
```

If that prints a version number, you are set. If not, install Git from the official [git-scm.com downloads page](https://git-scm.com/downloads), which has installers for Windows, macOS, and Linux. Then run the command again to confirm.

**On Windows, use Git Bash for this track.** The Git for Windows installer also installs **Git Bash**, a small bash terminal. Open it from the Start menu and run every command in this track there. Git itself works the same in PowerShell, but the shell around it does not: in Windows PowerShell, `echo "text" > file.txt` saves the file in an encoding (UTF-16) that Git treats as binary, so `git diff` would show "Binary files differ" instead of the changed lines. Git Bash avoids that, and the commands then match macOS and Linux exactly.

Now tell Git who you are. Every commit you make is permanently stamped with this name and email. It is the "who" in the audit trail described above.

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

Use your real name. For the email, think about where your commits will end up. In the next track you push commits to GitHub, and anyone who can see a repository can read the email in its commits. If you do not want your personal address public forever, use the private `noreply` address GitHub gives every account (on GitHub: **Settings → Emails**, it looks like `12345678+yourname@users.noreply.github.com`). GitLab offers the same thing under **Edit profile → Commit email**. This is a small privacy habit worth having before your first push, not after.

Set one more thing while you are here:

```bash
git config --global init.defaultBranch main
```

When Git creates a new repository, it also creates a first branch. Many installs still name that branch `master` by default. This track, GitHub, and GitLab all use `main`, and later commands like `git switch main` only work if the names match. This line makes every new repository start on `main`.

`--global` applies these settings to every repository on your machine, not just one. Check that they worked:

```bash
git config --global user.name
git config --global user.email
git config --global init.defaultBranch
```

## Creating your practice space

As in the other hands-on tracks, you will reuse one folder for every exercise:

```bash
mkdir -p ~/git-fundamentals && cd ~/git-fundamentals
```

`~` is your home folder, so the practice folder always ends up in the same place, no matter where your terminal opened. `-p` means "no error if it already exists", so this line is safe to run again on another day. From here on, "in your terminal" means from inside this folder unless a lesson says otherwise. Every later lesson starts by going back into it.

### What to notice

- Every commit is permanently labeled with a name and email, set once with `git config --global`. That is why the name should be real, and why the email should be one you are happy to make public, such as a `noreply` address.
- Because Git is distributed, every copy of a repository holds the full history, not just the latest state.
- Infrastructure as code and detection as code are why security work increasingly means reading Git history directly, not just a dashboard built on top of it.
