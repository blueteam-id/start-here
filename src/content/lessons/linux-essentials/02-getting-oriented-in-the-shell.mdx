## Before you start: getting a terminal

Lesson 1 was mostly reading. In this lesson you start typing, so you need a terminal open.

**On macOS or native Linux,** you already have one. Open the Terminal app (macOS) or your distro's terminal application. Nothing to install.

**On Windows,** install the **Windows Subsystem for Linux (WSL)**. It gives you a real Linux environment running alongside Windows, not an imitation. Open PowerShell as Administrator (right-click it, then "Run as administrator") and run:

```powershell
wsl --install
```

Follow the prompts and restart if asked. You end up with an Ubuntu terminal that you open like any other app. Full details and troubleshooting are in [Microsoft's WSL install docs](https://learn.microsoft.com/windows/wsl/install).

This is the only time this track explains the Windows setup. From now on, "your terminal" means macOS Terminal, native Linux, or WSL.

One detail before you start: macOS uses the **zsh** shell by default (since 2019), while Linux and WSL use **bash**. Every command in this track works the same in both. The only visible difference is the prompt symbol, explained below.

## What a shell is

A **shell** is a program that reads the line you type, works out what you mean, and asks the kernel to do it. "The command line" and "the terminal" usually mean the same thing: a shell waiting for input inside a terminal window. This track uses **bash**, the default on Linux and WSL. On macOS, zsh reads everything below the same way.

The line where you type is the **prompt**. Learn to read it instead of skipping over it. A typical prompt looks like this:

```bash
alex@webserver01:~/linux-essentials$
```

Piece by piece:

- `alex` is the **username** you are logged in as.
- `webserver01` is the **hostname**, the name of the machine. When you are connected to several servers at once, this is how you avoid running a command on the wrong one.
- `~/linux-essentials` is your **current directory**. `~` is short for your home directory.
- The last symbol tells you how powerful you are right now. In bash, `$` means an ordinary user. `#` means **root**, the superuser who can do anything, including destroy the system. In zsh (macOS), the ordinary-user symbol is `%` instead of `$`. `#` means root in both. Some distros also color the root prompt red.

Build one habit now: glance at that last character before you press Enter.

## Creating your practice space

This track uses one dedicated folder for all hands-on work. Create it and move into it:

```bash
mkdir -p ~/linux-essentials && cd ~/linux-essentials
```

- `mkdir` makes a new directory (folder).
- `-p` means "no error if it already exists, and create any missing parent folders".
- `&&` means "then run the next command, but only if the first one worked".

Every exercise in this track happens inside `~/linux-essentials`. You can fill it with test files, break things, and clean up without touching anything that matters. When a later lesson says "run this", it means from inside this folder unless it says otherwise.

## Where am I? pwd

On any unfamiliar system, the first question is "where am I?"

```bash
pwd
```

`pwd` means **print working directory**. It prints the full path of the folder your shell is in. After the `cd` above, it should end in `/linux-essentials`.

## What is here? ls

The next question is "what is in here?" That is `ls` (list):

```bash
ls
```

Your folder is empty, so this prints nothing. Add two flags for a richer view:

```bash
ls -la
```

- `-l` is the "long" format: one entry per line, with permissions, owner, size, and date.
- `-a` also shows **hidden** entries, whose names start with a dot. Plain `ls` leaves them out.

You should see two entries you did not create: `.` (this directory) and `..` (its parent). The column at the start of each line, something like `drwxr-xr-x`, shows who may do what to each file. You will learn to read it in Lesson 5.

## Moving around: cd

`cd` (change directory) moves you between folders. Try these, reading the comments as you go:

```bash
mkdir notes
cd notes      # relative path: move into "notes", found inside the current directory
pwd

cd /tmp       # absolute path: starts with "/", so it always means the same place
pwd           # regardless of where you started from

cd ~/linux-essentials   # absolute again, using the ~ shortcut for your home directory
pwd

cd notes
cd ..         # ".." always means "one level up", so this goes back up to linux-essentials
pwd

cd -          # the dash jumps you back to whichever directory you were just in
pwd
```

There are two kinds of path:

- A **relative** path (`notes`, `../notes`, `./notes`) starts from where you are now. The same command can land you in different places depending on where you start.
- An **absolute** path (starting with `/`, or with `~`) always means the same place.

When precision matters, use absolute paths. For short hops between nearby folders, relative paths save typing.

## Getting help without leaving the terminal

Nobody remembers every flag. What experienced people do remember is how to look things up. Two ways work almost everywhere:

```bash
man ls
```

`man` opens the **manual page** for a command: what it does, and every option it accepts. It opens in the same pager as `less` (Lesson 4): use the arrow keys to scroll, `/` to search for a word, and `q` to quit.

```bash
ls --help
```

Most Linux commands also print a shorter summary with `--help`. On macOS, many built-in commands do not support `--help` and print an error instead; use `man` there.

When you are not sure whether something is a real program or a shell shortcut, ask the shell:

```bash
type cd
type ls
```

On a server you have never seen before, `man` and `--help` are often the only documentation available. Reading them is a skill, not a sign that you are behind.

## Why this is worth practicing

`pwd`, `ls`, and `cd` look almost too simple for a whole lesson. But they are the first three commands nearly every analyst runs on an unfamiliar server. That is true whether the shell came from a planned SSH login or from a foothold during an incident. The first questions are always the same: where am I, what is here, and how do I get where I need to look.

If basic navigation takes your attention, you have less left for the real work: the suspicious process, the strange file, the log entry that does not fit. Making these commands automatic frees your attention for the investigation.

### What to notice

- `$` versus `#` is not cosmetic. Running the wrong command as root, on the wrong machine, is a common way incidents get worse.
- `ls -la` gave you a first look at file permissions. Lesson 5 explains how to read them.
- Your `~/linux-essentials` folder stays for the whole track. You do not need to clean it between lessons; later lessons say when to add or remove something.
- When you forget an option, `man` and `--help` are always there.
