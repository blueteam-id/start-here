## Back to the practice folder

```bash
cd ~/linux-essentials
```

Every command below runs inside this folder. To search for something, you first need something to search. Create a small sample log file:

```bash
cat > sample.log << 'EOF'
2024-01-10 08:12:01 INFO Starting service
2024-01-10 08:14:33 WARN Disk usage at 85%
2024-01-10 08:17:02 Failed password for root from 203.0.113.9
2024-01-10 08:17:05 Failed password for root from 203.0.113.9
2024-01-10 08:17:09 Failed password for admin from 203.0.113.9
2024-01-10 08:22:14 INFO Backup completed
2024-01-10 08:30:00 ERROR Disk write failure on /dev/sdb1
EOF
```

You now have `~/linux-essentials/sample.log`. It is small enough to read at a glance, and big enough to try every command below on real data.

## cat, less, and more: reading a file

For a short file, `cat` prints the whole thing:

```bash
cat sample.log
```

That works for seven lines. It stops working for a file thousands of lines long, like a real `/var/log/auth.log` on a busy server: the text scrolls past faster than you can read. For long files, page through with `less`:

```bash
less sample.log
```

`less` shows one screen at a time. Use the arrow keys or Page Up/Page Down to move, and press `q` to quit. You may also see `more`, an older and more limited pager. Default to `less`.

## head and tail: just the edges

Often you only care about one end of a file. `head` shows the first lines:

```bash
head sample.log
```

`tail` shows the last lines:

```bash
tail sample.log
```

Both show ten lines by default. Use `-n` to change that:

```bash
head -n 3 sample.log
tail -n 3 sample.log
```

There is one more form of `tail` worth knowing: `tail -f` **follows** a file, printing new lines as they are added, instead of exiting at the end. It is how you watch a log update in real time. You will try it live at the end of this lesson.

## grep: finding things inside files

`grep` does the actual searching, and it is the command most worth knowing well. In its simplest form, it prints every line that contains some text:

```bash
grep "Failed password" sample.log
```

That returns the three failed login lines and nothing else. This is almost exactly what a defender does on a real system. Files like `auth.log` and `syslog` get searched this way for:

- signs of a **brute-force attack**, such as "Failed password" many times in a short window,
- a known **indicator of compromise** (IOC): a filename, part of a hash, or an IP address you were told to look for.

A few flags make `grep` much more useful.

`-i` ignores case, so it matches `ERROR`, `Error`, and `error`:

```bash
grep -i "error" sample.log
```

`-n` shows the line number of each match:

```bash
grep -n "Failed password" sample.log
```

`-r` searches every file inside a folder. This turns `grep` from a one-file tool into one you can point at a whole folder of logs:

```bash
mkdir -p logs
cp sample.log logs/auth.log
grep -r "Failed password" logs
```

`-v` inverts the match: it prints every line that does **not** contain the text. Use it to filter out noise you already understand, so only the unusual lines remain:

```bash
grep -v "INFO" sample.log
```

## Pipes and redirection: chaining commands together

The pipe `|` sends the output of one command into the next one, instead of to your screen:

```bash
cat sample.log | grep ERROR
```

That example is a little redundant, since `grep ERROR sample.log` does the same. The pattern is what matters: pipes let you combine small, single-purpose commands. A common defender move is to count matches instead of reading them all, with `wc -l` (word count, `-l` for lines):

```bash
grep "Failed password" sample.log | wc -l
```

One number answers "how many failed logins are in this file?" It works the same on a seven-line sample and on a huge `auth.log`.

**Redirection** sends output to a file instead of the screen. `>` creates or overwrites a file:

```bash
grep "Failed password" sample.log > failed-logins.txt
cat failed-logins.txt
```

`>>` adds to the end of a file instead of overwriting it:

```bash
echo "Reviewed by analyst on duty" >> failed-logins.txt
cat failed-logins.txt
```

Both stay inside `~/linux-essentials`, so a mistake costs nothing.

## Editing a file by hand: nano

Redirection is great for scripts, but sometimes you just need to open a file and change a line. `nano` is a small text editor that runs inside the terminal and works on Linux, WSL, and macOS:

```bash
nano failed-logins.txt
```

Use the arrow keys to move and type as usual. Add a line at the bottom, such as `Checked again after lunch`. To save, press `Ctrl+O`, then `Enter`. To exit, press `Ctrl+X`. Check your change:

```bash
cat failed-logins.txt
```

The shortcuts are listed at the bottom of the `nano` screen, where `^` means `Ctrl`. Later tracks (Git, and the server track) will ask you to edit files, and `nano` is all you need for that.

## Watching a file live: tail -f

This one needs **two terminal windows**, both inside `~/linux-essentials`. In the first one, start following the log:

```bash
tail -f sample.log
```

It prints the last lines and then waits. In the second window, add a new line to the same file:

```bash
cd ~/linux-essentials
echo "2024-01-10 08:31:00 Failed password for root from 203.0.113.9" >> sample.log
```

Look back at the first window: the new line appears there by itself. That is what watching an authentication log during an active incident looks like, just at a much smaller scale. Press `Ctrl+C` in the first window to stop following. `Ctrl+C` stops almost any command that is still running in the foreground, which is worth remembering on its own.

### What to notice

- Use `cat` for short files and `less` for long ones. `q` gets you out of `less`.
- `grep`, with `-i`, `-n`, `-r`, and `-v`, is the search tool you will use most, including on real `auth.log` and `syslog` files.
- Pipes and redirection turn a pile of log lines into one specific answer, like a count.
- `nano` edits a file, `tail -f` watches one live, and `Ctrl+C` stops a running command.
