## Getting back to your practice folder

Every exercise in this lesson happens inside the folder you created in Lesson 2. Open your terminal and go there:

```bash
cd ~/linux-essentials
```

If a command ever does something unexpected, run `pwd` first to confirm where you are.

## Absolute vs relative paths, properly this time

Lesson 2 introduced the two kinds of path. They deserve a closer look, because misreading a path is a common way to run a command on the wrong file.

- An **absolute path** starts at the top of the filesystem, the root directory, written as `/`. It names every folder on the way down, so it always means the same place. Example: `/home/alex/linux-essentials`.
- A **relative path** has no leading `/`. It means "starting from where I am now". Examples: `notes`, `../notes`, `./notes`.

Two special names come up constantly:

```bash
mkdir -p project/subfolder
cd project/subfolder
pwd

cd .
pwd

cd ..
pwd

cd ~/linux-essentials
```

- `.` means "this same directory", so `cd .` does nothing.
- `..` means "the parent directory", one level up.

Every directory quietly contains a `.` and a `..` entry. You will see them again with `ls -a` below.

Small differences in a path matter. `rm notes` and `rm ../notes` are one character apart, but they can delete two completely different things. When in doubt, run `pwd` first, or use the absolute path.

## A quick tour of the real filesystem

So far you have stayed inside your practice folder. Linux systems all share a similar layout above it, and a defender needs to know the main stops. Looking is always safe, so take a read-only tour. Run each line and read the output:

```bash
ls /
ls /etc
ls /var/log
ls /tmp
```

What you are looking at:

- `/` is the **root** of the whole filesystem. Everything lives somewhere below it.
- `/etc` holds **system configuration**: users, network settings, and the settings of installed services. When a server is misconfigured, the mistake is usually in a file here.
- `/var/log` holds **log files**. On many systems you will see names like `syslog` or `auth.log` (login activity). Some modern systems keep most logs in the systemd journal instead, so this folder may look sparse. Either is normal. You do not need to open these files now; some need extra privileges to read.
- `/tmp` is **temporary storage** that every user can write to. Like `%TEMP%` on Windows, it is a classic place for an attacker to drop a file.
- `/home` holds each user's home folder on Linux (`~` is yours). On macOS, home folders live under `/Users` instead.

Do not create, change, or delete anything outside `~/linux-essentials`. The tour is for reading only. Knowing these few locations means that when an alert says "suspicious file in `/tmp`" or "check `/var/log/auth.log`", you already know where you are going.

## Hidden files: what dotfiles are, and why defenders care

Run this inside your practice folder:

```bash
touch .hidden-config
ls
ls -a
```

Plain `ls` shows your `project` folder but not `.hidden-config`. `ls -a` shows everything: `project`, `.hidden-config`, `.`, and `..`.

Names that start with a dot are **dotfiles**, and they are hidden by default for an ordinary reason. Most are settings and state, like `.bashrc` or `.gitconfig`. You rarely need to see them while working, so the tools keep them out of the way.

That same convenience is why dotfiles matter to a defender. People stop looking closely at things they cannot see by default, and attackers know it. Real incidents include payloads named `.cache`, scripts hidden inside `.config/systemd/.hidden/`, and backdoors named to look like normal dotfiles. None of this is advanced. It works because the default view does not show it.

The habit to build now: when you are **investigating** a system, not just browsing it, always use `ls -a`. An unfamiliar dotfile, or one in a place it has no reason to be, deserves a second look.

## Building structure: mkdir and touch

`mkdir` makes directories. With `-p`, it also creates any missing parent folders:

```bash
mkdir -p reports/2024
ls -la reports
```

`touch` creates an empty file if it does not exist. If it does exist, `touch` only updates its modification time:

```bash
touch reports/summary.txt
ls -la reports
```

With these two commands you can build any practice structure you need inside `~/linux-essentials`.

## Copying, moving, and removing

`cp` copies a file and leaves the original in place:

```bash
cp reports/summary.txt reports/summary-backup.txt
ls -la reports
```

`mv` moves or renames a file. After a move, the old location no longer has the file:

```bash
mv reports/summary-backup.txt reports/2024/summary-backup.txt
ls -la reports/2024
```

`rm` removes a file:

```bash
rm reports/2024/summary-backup.txt
ls -la reports/2024
```

<Callout type="warning">

This is the most important sentence in the lesson: **`rm` has no undo.** There is no recycle bin and, by default, no "are you sure?" question. The file is gone.

</Callout>

That is why every example here runs inside `~/linux-essentials`. Here, a mistake costs nothing. The same command on a real system, one folder off, cannot be reversed. Before any deletion, check where you are with `pwd` and what is there with `ls`.

Plain `rm` refuses to remove a directory. Add `-r` (recursive) to remove a directory and everything inside it:

```bash
mkdir scratch
touch scratch/throwaway.txt
rm -r scratch
ls -la
```

`-r` is what makes `rm` dangerous at scale: one flag, and a whole tree of files is gone. Treat it as an irreversible action, even here.

## Wildcards: acting on many files at once

Real work often involves many files at once. **Wildcards** let one command match a pattern of names. Create some files to try:

```bash
touch app.log error.log access.log notes.txt readme.txt
ls
```

`*` matches any sequence of characters, including none:

```bash
ls *.log
rm *.log
ls
```

That removed the three `.log` files and kept the two `.txt` files, because `*.log` only matches names ending in `.log`.

`?` is narrower. It matches **exactly one** character:

```bash
touch notes.txt note1.txt note2.txt noteA.txt note10.txt
ls note?.txt
```

`note?.txt` matches `notes.txt`, `note1.txt`, `note2.txt`, and `noteA.txt`. It does not match `note10.txt`, because `10` is two characters.

Wildcards save time, and they also multiply mistakes. `rm *.log` is fine after a plain `ls *.log` has shown you exactly what matches. `rm *` in the wrong folder, in a hurry, deletes everything there. The habit: **run the pattern with `ls` first**, then with `rm`, `mv`, or anything else that changes files.

### What to notice

- `.` and `..` are real entries in every directory. They are what makes `cd ..` work.
- Hidden files only reduce clutter. They are not a security boundary, which is why attackers use them to stay unnoticed.
- `rm` and `rm -r` deserve a little fear. Keep that caution, and increase it once you leave the practice folder.
- A few locations are worth knowing by heart: `/etc` for configuration, `/var/log` for logs, `/tmp` for temporary files.
