## Where the name "Linux" comes from

The story starts with **Unix**. Researchers at Bell Labs built it in 1969. It was simple and portable, and it was built from small tools that each did one job well. Over time, Unix became tied up in commercial licenses. By the early 1980s, there was no Unix-like system that people were free to study, change, and share.

In 1983, Richard Stallman started the **GNU project** to fix that. Its goal was a complete, free, Unix-compatible operating system. GNU produced many of the parts: a compiler, a text editor, a shell, and the basic command-line tools. One central piece was still missing: the **kernel**, the program that talks to the hardware and decides which process gets the CPU, memory, and files.

That piece arrived in 1991. A Finnish student, Linus Torvalds, posted that he was writing a kernel, calling it "just a hobby". Combined with the GNU tools, his kernel completed a free operating system. That kernel is **Linux**.

Strictly speaking, "Linux" is only the kernel. The complete system around it is a **GNU/Linux distribution**. In everyday speech, and in the rest of this track, people say "Linux" for the whole system. The difference still matters in security work:

- A **kernel vulnerability** is a bug in Linux itself. It is fixed by a kernel update.
- A bug in a **package** (a tool shipped with the distro) is fixed by updating that package.

They are reported in different places and patched on different schedules.

## What a "distro" is

You cannot log in to a bare kernel. A **distribution** ("distro") packages it into something you can install and use. A distro bundles:

- the Linux kernel,
- GNU and other everyday tools,
- a **package manager** for installing and updating software,
- default settings chosen by the people who maintain it.

Choosing a distro means choosing who you trust to make those decisions for you. The major families you will meet:

- **Debian family.** Debian focuses on stability and free software, with a careful release process. **Ubuntu** is built on Debian and is friendlier out of the box. It is the most common choice on cloud servers and for beginners.
- **Red Hat family.** **Red Hat Enterprise Linux (RHEL)** is a paid, supported distro for businesses. **Fedora** is the faster-moving community distro where new features are tested first. **Rocky Linux**, **AlmaLinux**, and **CentOS Stream** are free options compatible with RHEL.
- **Arch Linux.** You build the system yourself, piece by piece, and it updates continuously ("rolling release"). Great for learning every layer, harder for beginners.
- **Security distros.** **Kali Linux** and **Parrot OS** come with hundreds of tools for penetration testing and forensics. Underneath, they are normal Linux systems, so everything in this track applies to them too.

There is no single best distro. Habits usually carry over inside a family: package names, where configuration files live, and so on.

## Where Linux runs

If you only know your own laptop, Linux can look like a niche choice. It is the opposite:

- Most public web servers run Linux.
- It is the most common operating system for virtual machines on every major cloud provider.
- **Android** is built on the Linux kernel.
- Every one of the world's 500 fastest supercomputers runs Linux.
- Home routers, smart TVs, payment terminals, and industrial devices often run it too.

For a defender, this is a career fact, not trivia. The web servers you monitor, the cloud workloads you check, the containers you audit, and the logs you read during an incident will mostly come from Linux systems. Knowing your way around Linux is an everyday part of the job.

## A quick look under the hood

You do not need to install anything to get your first real look at a Linux system. If you are on native Linux, open a terminal and run the two commands below. If you are on Windows, you will install WSL (a real Linux environment inside Windows) at the start of Lesson 2; skip this step for now, and come back to it once WSL is set up.

```bash
uname -a
cat /etc/os-release
```

- `uname -a` prints the **kernel** version and the processor architecture.
- `cat /etc/os-release` prints the **distro** name and version.

Read the output slowly. You should recognise a kernel version number and a distro name from this lesson.

**On macOS**, `uname -a` still works, but it reports **Darwin** and the **XNU** kernel instead of Linux. `cat /etc/os-release` fails, because that file is a Linux convention. This is expected. macOS is a certified Unix system, but it is not Linux: it has its own kernel and its own tools. For this track, the difference only matters in Lesson 6, where macOS installs software with Homebrew instead of `apt`. Every other command works the same.

### What to notice

- `uname -a` and `cat /etc/os-release` give you the two facts most troubleshooting guides and security advisories ask for first: the kernel version, and the distro and its version.
- "The kernel" and "the distro" are patched by different people on different schedules. Knowing which one a problem is in tells you what to update.
- Over the next lessons, watch how much of what feels "distro-specific" is really just a convention one family shares.
